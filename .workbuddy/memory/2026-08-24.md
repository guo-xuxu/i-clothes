## git 对象库损坏 + 修复（pull 4cd28c0 过程）

- **根因**：WorkBuddy Bash 沙箱对 `.git/` 元数据写入跨命令回滚（同一命令内可见、下条命令丢失）。普通沙箱内 checkout 弄丢 `.git/refs/heads/` 目录 → HEAD 指向不存在 ref；多次 fetch 使 git 自动管理对象时 pack 写入被回滚 → loose objects 被清、pack 不完整 → `bad object a6ce07a/77aab82`、`not a git repository`。
- **修复流程（已验证有效）**：① 备份 `.git` → `.git.bak-20260824`；② 清理损坏内部（`rm -rf .git/objects .git/refs .git/index .git/logs .git/packed-refs`，保留 config）；③ `git fetch origin` 完整重建对象（远端有全部提交）；④ **用单文件 `packed-refs` 写引用**（`printf '<sha> refs/heads/<name>\n' > .git/packed-refs`）——比散落 ref 文件跨命令持久；⑤ 重建 index：`git read-tree HEAD && git checkout-index -a -f`；⑥ 同一命令内验证。
- **当前状态（已修复）**：本地 3 分支 main(a6ce07a) / feat/springboot-migration(4cd28c0, HEAD) / feat/knowledge-graph-rag(b631dd4)；远端 3 分支齐全；工作区已切到 springboot 分支（98 文件）。注意：RAG 文档(2026-08-23-*.md)在工作区消失属正常——它们在 feat/knowledge-graph-rag 分支，切回即恢复。`docs/superpowers/specs/` 现为 springboot 内容。
