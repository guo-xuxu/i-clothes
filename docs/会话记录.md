## 3. 架构核心知识（message 链路，务必保留）

**用户 message → Python 的完整链路**（逐跳代码位置）：

```
前端 api.js → POST /api/chat {conversation_id, message, images}
  → Java ChatController（校验 400/429）
  → ChatService.chat() [iclothes-server/.../service/ChatService.java:37]
      ├─ :40-42 会话解析/新建
      ├─ :47   Redis 写锁（conversation:{id}:lock，等待≤3s，超时 503）
      ├─ :54   从 PG 取最近 20 条历史 lastMessages(cid, 20)
      ├─ :55-57 历史 → AgentChatRequest.HistoryItem 列表
      └─ :58   ★ agentClient.chat(message, images, historyItems)
  → PythonAgentClient.chat() [.../agent/PythonAgentClient.java:43]
      RestClient POST http://127.0.0.1:8000/api/agent/chat
      Body: {"message","images","history"}（Jackson 序列化）
  → Python agent.py:52 agent_chat（pydantic AgentChatRequest 反序列化）
      → run_chat → LangGraph（intent_router → chat/recommend）→ {reply, intent}
  → 原路返回 → ChatService 落库（事务：append user+assistant/touch/trim/标题）
  → ChatResponse → 前端
```

**三个本质**：
- 地址/超时在 `RestClientConfig.java`（baseUrl 默认 `http://127.0.0.1:8000`，connect 3s/read 60s）
- Java 的 `AgentChatRequest`(record) 与 Python 的 `AgentChatRequest`(pydantic) 是"镜像双胞胎"= 契约，字段名谁都不能单独改
- **Python 无状态**：所有信息（message/images/history）都在请求体里，Python 零数据库连接；历史由 Java 从 PG 现取现带
