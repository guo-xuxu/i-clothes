# i-clothes 部署指南（Docker Compose 方式）

> 适用：Ubuntu/Debian 类 Linux 服务器，目标是把「双服务 + PG + Redis」四件套跑起来，
> 浏览器通过 **Java :8080**（伺服前端 + 业务）访问，Python Agent 仅内网被 Java 调用。
> 部署形态即仓库交付的 `docker-compose.yml`（迁移期的交付物）。

## 0. 架构回顾（部署视角）

```
浏览器 ── :8080（公网）──> Java 业务后端（iclothes-server）
                            │  ├─ PostgreSQL :5432（容器内网）
                            │  └─ Redis :6379（容器内网）
                            └── HTTP ──> Python Agent :8000（容器内网，不对外）
                                            └─ LLM：千问（图片/embedding）+ DeepSeek（文本）
                                            └─ 知识库：app/knowledge/data/（graph.json + Chroma，文件）
```

**两个部署前提（重要）**：
- Java 镜像的 Dockerfile 是 `COPY iclothes-server/target/*.jar` 和 `COPY frontend/dist`——
  **JAR 和前端 dist 必须先在本地构建好**，仓库里没有这两个构建产物。
- 知识库数据 `app/knowledge/data/`（graph.json、chroma、synonyms.json、processed_docs.json）
  是 **git-ignored**，clone 下来是空的——需要拷贝过去，或在服务器上重建。

## 1. 本地准备（构建产物 + 数据）

在开发机（本仓库）执行：

```powershell
# ① 构建前端 dist（frontend/dist）
cd frontend
npm install
npm run build

# ② 构建 Java JAR（需 JDK 21 + Maven）
cd D:\code\i-clothes
$env:JAVA_HOME='D:\language\java21'; $env:PATH="D:\language\java21\bin;D:\language\maven\bin;$env:PATH"
mvn -f iclothes-server/pom.xml package -DskipTests
# 产出：iclothes-server/target/iclothes-server-0.1.0.jar

# ③ 确认知识库数据存在（如已全量入库，应有这些文件）
Get-ChildItem app\knowledge\data -Recurse -File | Select-Object FullName
```

**知识库数据二选一**：
- **A. 拷贝数据**（推荐，免重建成本）：把整个 `app/knowledge/data/` 目录随代码一起传到服务器；
- **B. 服务器上重建**：部署完成后调 `POST /api/knowledge/import`（后台全量入库，约 1 小时 + LLM 费用）。

然后推送代码（或直接打包上传目录）：

```bash
git add -A && git commit -m "build: frontend dist and jar" && git push
# 若 data/ 未进 git，用 scp 单独传：
# scp -r app/knowledge/data user@server:/path/i-clothes/app/knowledge/
```

## 2. 服务器准备（一次性）

```bash
# ① 安装 Docker + compose 插件（Ubuntu 示例）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER && newgrp docker
docker compose version   # 确认 compose v2

# ② 拉代码
git clone <你的仓库地址> i-clothes
cd i-clothes

# ③ 补知识库数据（选 A 的话）
# scp -r 传上来后解压/放置到 app/knowledge/data/，确认：
ls app/knowledge/data/graph/graph.json   # 有文件才算有知识库

# ④ 配置环境变量（.env，不提交进 git）
cat > .env <<'EOF'
QIANWEN_API_KEY=sk-你的千问key
DEEPSEEK_API_KEY=sk-你的deepseekkey
DB_PASSWORD=换一个强密码
EOF
chmod 600 .env
```

---

## 3. 构建并启动

```bash
docker compose up -d --build
```

第一次会构建两个镜像（Python 装依赖 + Java 用本地 JAR），耐心等几分钟。

## 4. 验证

```bash
curl http://127.0.0.1:8080/api/health
# 期望：{"status":"ok","qianwen_configured":true}

# 浏览器打开 http://<服务器IP>:8080 应看到前端
# 发一条消息验证全链路（含检索）：
curl -X POST http://127.0.0.1:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"参加婚礼穿什么","images":[]}'

docker compose ps        # 四个服务应全部 healthy/running
docker compose logs -f iclothes-python   # 看意图分析/在线召回日志
```

## 5. 生产注意事项

| 项 | 建议 |
|---|---|
| 端口暴露 | 只把 **8080** 暴露公网；`8000`（Python）、`5432`（PG）、`6379`（Redis）保持容器内网或防火墙仅限本机 |
| HTTPS | 用 Caddy/nginx 反代 8080（Caddy 自动签证书：`caddy reverse-proxy --from your.domain --to :8080`） |
| 知识库持久化 | `app/knowledge/data/` 已挂卷（`knowledge-data` 卷），容器重建不丢数据；**新入库的数据请保留在卷里**，不要把 `docker compose build` 后镜像内的旧数据当最新 |
| 数据库持久化 | PG 数据在 `pgdata` 卷，天然持久 |
| 更新发布 | 本地重跑 `npm run build` + `mvn package` → 提交 → 服务器 `git pull` → `docker compose up -d --build` |
| 时区/日志 | `docker compose logs` 查应用日志；Phoenix（6006/4317）只在容器内网，不影响对外 |
| 资源 | 最低 2C4G 可跑；LLM 调用是网络请求，不占服务器算力 |
| 安全 | `.env` 权限 600；不要公开 8000（无鉴权、直接烧 LLM 费用） |

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| Java 起不来报 DB 连接失败 | 等 PG healthy（`depends_on` 已处理）；确认 `.env` 的 DB_PASSWORD 与 compose 默认一致（或都用 `DB_PASSWORD` 变量） |
| 健康检查 qianwen_configured=false | 检查 `.env` 的 QIANWEN_API_KEY 是否传入容器（`docker compose exec iclothes-server env`） |
| 问答不引用知识库 | 确认 `app/knowledge/data/graph/graph.json` 存在（`docker compose exec iclothes-python ls /app/app/knowledge/data/graph`）；没有就跑一次入库接口重建 |
| 构建极慢 | 确认 `.dockerignore` 存在（本仓库已加，排除了 .conda/node_modules/.git）；首次 pip install 慢属正常 |

## 7. 备选：不用 Docker（裸进程跑）

服务器装 JDK 21 + Python 3.12 + PostgreSQL + Redis 后，等价于本机开发模式：

```bash
# 终端 1：Python Agent
cd i-clothes && set -a && . ./.env && set +a
nohup python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 &

# 终端 2：Java（需要 PG/Redis 已在跑 + frontend/dist 存在）
nohup java -jar iclothes-server/target/iclothes-server-0.1.0.jar &

# systemd 托管（推荐）：为两个服务各写一个 unit 文件
```

本指南以 Docker Compose 为主（交付物形态），裸进程方式与本地开发一致。
